# Очистка заявок из XLSX

Нужны Windows и Python 3.10 или новее. Excel для выполнения скрипта не нужен.
Заголовки в первой строке: `Имя`, `Телефон`, `Дата заявки`, `Источник`.
Порядок колонок может быть другим. Полностью пустые строки пропускаются.

## Быстрый запуск в Windows

1. Распакуйте архив целиком в папку с латинским именем. Откройте вложенную
   папку `zayavki-test`, в которой находятся `run.cmd` и `clean_zayavki.py`.
2. Установите Python с python.org, включив **Add Python to PATH**.
3. Дважды щёлкните `run.cmd`. Он создаст `.venv`, установит зависимость и
   обработает приложенный `zayavki.xlsx`. Для первой установки нужен интернет.
4. Откройте `results\zayavki_clean.xlsx` и `results\zayavki_problems.xlsx`.
   Готовые результаты уже приложены; запуск без аргументов их обновляет.
   Перед обновлением закройте файлы результатов в Excel.

Другой файл, из PowerShell в папке скрипта:

```powershell
.\run.cmd "C:\Data\new.xlsx" --period 2027-04 --out-dir "C:\Data\result"
```

В CMD используйте `run.cmd` без префикса `.\`.
Можно перетащить другой XLSX на `run.cmd`. Период тогда определяется автоматически.
Если у файла несколько месяцев, используйте `--no-infer-period`.

## Запуск Python напрямую

Выполните из папки скрипта в PowerShell. Если `.venv` уже создана через
`run.cmd`, первые две команды можно пропустить:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe clean_zayavki.py zayavki.xlsx --period 2026-09 --out-dir results --force
```

Минимальный вызов:

```powershell
.\.venv\Scripts\python.exe clean_zayavki.py "C:\Data\new.xlsx"
```

На выходе рядом с входным файлом появятся `new_clean.xlsx` и `new_problems.xlsx`.
Флаг `--out-dir` меняет папку результатов, `--force` разрешает их перезапись.
Исходный файл скрипт не изменяет. Без `--force` существующие результаты защищены.
Код возврата: `0` — обработка выполнена, `1` — ошибка файла/записи,
`2` — неверные аргументы. Наличие проблемных строк не является сбоем запуска.

Дополнительные параметры:

```powershell
.\.venv\Scripts\python.exe clean_zayavki.py new.xlsx --sheet "Заявки"
.\.venv\Scripts\python.exe clean_zayavki.py new.xlsx --no-infer-period --slash-order dmy
.\.venv\Scripts\python.exe clean_zayavki.py --help
```

## Правила очистки

**Телефон.** Принимаются 10 цифр местного номера или 11 цифр с префиксом `7`/`8`;
результат — `+7XXXXXXXXXX`. Пробелы, скобки, дефисы и подпись `тел.` допустимы.
Примечание `после 18:00` рядом с телефоном не становится частью номера.
Схема записи с подписью: `тел.: 8 (XXX) XXX-XX-XX (после 18:00)`;
в реальных данных вместо `X` должны быть цифры.
Недостаточное/избыточное число цифр, чужой международный префикс,
номер с ведущим нулём или из одной повторяющейся цифры — проблема.
Несколько разных телефонов в одной ячейке требуют проверки; скрипт не выбирает один.
Проверяется формат, а не существование номера у оператора.

**Дата.** Поддерживаются Excel-даты/числовые серийные даты, ISO-даты,
`ДД.ММ.ГГГГ`, `ДД-ММ-ГГГГ`, `ГГГГ/ММ/ДД`, русские названия месяцев и двухзначный год.
Двухзначный год означает 2000–2099. Результат — текст `YYYY-MM-DD`.
Даты через `/` с годом в конце могут быть `ДД/ММ/ГГГГ` или `ММ/ДД/ГГГГ`.
В режиме `auto` неоднозначная дата принимается только когда ровно один вариант
попадает в ожидаемый месяц. Иначе строка попадает в проблемы с обоими вариантами.
`--slash-order dmy` или `mdy` задаёт единый порядок для таких дат во всём файле.
Невозможные даты не исправляются.

**Период.** Для предоставленного файла указан `--period 2026-09`, как в задании.
На другом файле без этого параметра месяц определяется, если на него приходится
строго больше половины однозначно распознанных дат и таких дат хотя бы две.
Это предположение о месячной выгрузке отражается в сводке. Если месяцы смешаны,
передайте `--no-infer-period`: даты вне одного месяца не будут отклоняться,
но неоднозначные даты и даты без года могут потребовать проверки.
При известном периоде `12 сентября` получает год периода.
`19.09.2062` сохраняется как `2062-09-19` в отчёте и помечается как дата вне периода;
скрипт не подменяет год на 2026.

**Имя.** Убираются лишние пробелы и невидимые символы; слова получают заглавную букву.
Очевидные латинские двойники букв заменяются только внутри слов с кириллицей:
например, латинская `e` заменяется на кириллическую `е`. Английские имена сохраняются. Порядок имени/фамилии
не угадывается, инициалы не разворачиваются автоматически.

**Дубли.** Группируются только распознанные телефоны. Строки без телефона
не объединяются друг с другом. Выбирается одна исходная запись:
сначала больше заполненных корректных полей `Имя`/`Дата`, затем больше полных
слов в имени, затем более ранняя дата, затем меньший номер исходной строки.
Значения из разных строк не склеиваются. Поэтому полное имя
имеет преимущество перед вариантом с инициалом, а строка с датой — перед строкой без даты.
Если выбранная запись не имеет имени/даты либо дата вне периода, в чистый файл
она не включается. Исходные строки остаются в отчёте.

**Конфликты имён.** Перестановка имени и фамилии, `е`/`ё` и совместимый инициал
не считаются конфликтом. Разные имена у одного телефона помечаются у всей группы.
По требованию задания один телефон всё равно даёт одну запись, включая `8-800`.
Выбранная запись с корректными обязательными полями входит в чистый файл,
а также в список проблем с предупреждением о конфликте. Группы с разными именами
и общим телефоном, в том числе номером `8-800`, требуют ручной проверки.

## Результаты на приложенном файле

- Исходных непустых строк: **48**.
- Чистых записей: **24**.
- Удалённых дублей: **18**.
- Проблемных записей без включения в чистый файл: **6**.
- Строк на листе `Проблемы`, включая дубли и конфликты: **26**.

Две выбранные записи с конфликтом имён также присутствуют в чистом файле.
Поэтому число строк на листе `Проблемы` не нужно складывать с числом чистых записей.

В `zayavki_clean.xlsx` — четыре исходные колонки в нормализованном виде.
В `zayavki_problems.xlsx`:

- `Проблемы` — причины, исходные и нормализованные значения, номер исходной строки
  и ссылка номером строки на выбранную запись для дубля.
- `Аудит` — все **48** исходных записей со статусами `Чистая`, `Дубликат`, `Проблема`.
  Каждая исходная запись имеет ровно один статус: **24 + 18 + 6 = 48**.
- `Сводка` — количество записей и способ выбора периода.

Даты и телефоны в выходных файлах — текст, чтобы Excel не менял формат.
Все исходные формульные строки в отчёте сохраняются текстом.
Необработанные дополнительные колонки вне четырёх обязательных в результат не входят.
При нескольких листах с обязательными заголовками нужно указать `--sheet`.

## Проверка

После первого запуска `run.cmd` выполните в PowerShell из папки скрипта:

```powershell
.\.venv\Scripts\python.exe -m unittest -v test_clean_zayavki.py
```

Тесты проверяют телефоны с примечаниями, неоднозначные и невозможные даты,
год/месяц другого файла, исправление пробелов/двойников букв, дубли,
конфликты имён, сохранение всех исходных строк и защиту от перезаписи.
`validation.txt` содержит результаты проверки предоставленного файла.
Логику Python проверили в Linux. Windows-обёртка подготовлена и проверена
по коду, фактический запуск Windows в этой среде недоступен.

## Что добавить перед отправкой задания

PDF требует все сессии работы с AI без редактирования. У скрипта и агента нет
инструмента экспорта этой беседы. Поэтому папка `ai_history` содержит указание
добавить настоящий экспорт из интерфейса AI. Пересказ и тестовый лог его не заменяют.
Необходимо экспортировать эту беседу полностью, включая окончательный ответ,
и все другие сессии по заданию, если они были, в `ai_history`, затем пересобрать ZIP.
Пароли, ключи и прочие разрешённые PDF сведения можно заменить на `[скрыто]`.

`reflection_draft.txt` — заготовка из шести строк. Перепишите её своими словами
и укажите только события, которые соответствуют вашей реальной работе.
Архив без полного экспорта истории ещё не соответствует комплектности сдачи из PDF.
